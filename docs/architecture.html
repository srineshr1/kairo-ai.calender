overview
How Kairo Works

Kairo is an AI-powered smart calendar. Connect WhatsApp, select groups to monitor, and Kairo automatically extracts events (exams, deadlines, meetings) from messages and images using Groq LLMs. A built-in AI assistant answers questions about your schedule.

🌐

Frontend SPA

React + Vite app deployed on Firebase Hosting with global CDN. Week/Day/Month views, drag-and-drop scheduling, AI chat sidebar, WhatsApp connection panel, and dark/light theme. Zustand for state, Supabase Realtime for live updates.

React 18Vite 5ZustandDnD Kitdate-fnsTailwind
⚙

Bridge Server (AWS EC2)

Express API running in Docker on an EC2 instance. Manages multi-tenant WhatsApp Web sessions via whatsapp-web.js + headless Chromium. Proxies Groq AI calls, processes messages for event extraction, and syncs state to Supabase.

Express 4whatsapp-web.jsChromiumDocker ComposeEC2 t3.micro
🗃

Supabase (Database + Auth)

Managed PostgreSQL with Realtime subscriptions and Row Level Security. Stores users, calendar events, WhatsApp status, chat history, and bridge API keys. RLS ensures each user can only access their own data.

PostgreSQLRealtimeAuth (JWT)RLSGoogle OAuth
🤖

Groq AI (LLM Inference)

Ultra-fast LLM inference for event extraction and chat. Llama 3.3 70B for text understanding, Llama 4 Scout for vision (timetable images, PDFs). API keys stay server-side, proxied through the bridge.

llama-3.3-70bllama-4-scoutVision OCRJSON mode
💬

WhatsApp Integration

Each user gets an isolated headless Chromium session authenticated via QR scan. Bridge monitors watched groups, intercepts messages, runs them through Groq for event extraction, and pushes structured events to Supabase in real-time.

Multi-tenantQR authGroup monitoringMedia download
🚀

CI/CD & Infrastructure

GitHub Actions auto-deploys the bridge to EC2 on push. Frontend builds with Vite and deploys to Firebase Hosting. Docker Compose orchestrates the bridge container with health checks and auto-restart.

security
Security Model

✓ Implemented

  • httpOnly JWT cookies for bridge auth — XSS-proof credentials
  • Row Level Security on all Supabase tables — queries scoped to auth.uid()
  • Service role key limited to 2 cross-user operations (boot cleanup, admin tasks)
  • User-scoped Supabase client with signed JWT for per-user writes
  • Bridge API key stored in Supabase (no file-based secrets)
  • Rate limiting: 120 req/min global, 30/min AI, 10/15min registration
  • Helmet security headers on bridge API
  • CORS whitelist with origin validation

⚠ Planned

  • TLS termination — Caddy/nginx reverse proxy with Let's Encrypt
  • Content Security Policy headers on Firebase Hosting
  • Restrict port 3001 behind reverse proxy (not 0.0.0.0)
  • Chrome sandbox inside Docker (currently --no-sandbox)
  • Brute-force protection on auth-cookie endpoint
  • Automated npm audit in CI pipeline
